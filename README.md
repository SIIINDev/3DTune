# 3DTune

Управление и настройка 3D-принтера **Kingroon KP5L** по USB — PID, геометрия, 3D Touch, сетка
стола, калибровки — из веб-интерфейса, доступного с любого устройства в локальной сети.
Тачскрин принтера не нужен.

**Статус:** Фаза 1 работает целиком, Фазы 2–3 в основном готовы. 38 тестов зелёные.
Разработка идёт против встроенного эмулятора Marlin — принтер и кабель для этого не нужны.

## Запуск

Нужен только Node 24+ (типы стираются рантаймом, сборки нет).

```bash
npm install
```

Против встроенного эмулятора Marlin — ничего подключать не надо:

```bash
npm run mock
```

В консоли появится ссылка с токеном (`http://127.0.0.1:8420/#t=…`) — открой её в браузере.

С реальным принтером:

```bash
node src/index.ts --list-ports
```

```bash
node src/index.ts --serial /dev/cu.usbserial-1420 --baud 115200
```

Доступ с телефона и других устройств в локальной сети:

```bash
node src/index.ts --serial /dev/cu.usbserial-1420 --host 0.0.0.0
```

Сервер напечатает LAN-ссылки с токеном. **Наружу в интернет не выставлять** — это управление
нагревателями; нужен удалённый доступ, используй VPN.

Прогон с имитацией помех на линии (проверка восстановления по `Resend`):

```bash
npm run mock:chaos
```

Тесты и типы:

```bash
npm test && npx tsc --noEmit
```

| **Мониторинг** | живые температуры, график с crosshair и тултипом, мощность нагревателей, позиция, эндстопы, терминал с журналом |
| **Управление** | джог XYZE, home, моторы, вентилятор, нагрев с пресетами, E-Stop |
| **Настройки** | `M503` → типизированные формы, отслеживание правок, панель «не применено» с точными GCode, батч-применение, отдельная кнопка `M500` |
| **PID** | мастер автотюна для сопла и стола, парсинг `bias:`/`Ku:`/`Tu:`/`Kp:`, применение `U1` |
| **Зонд / 3D Touch** | deploy/stow/самотест, редактор `M851`, живая подстройка `M290` с фиксацией в `M851`, `G29`, diverging-карта сетки, `M420 S1/S0` |
| **Безопасность** | клампы температур на сервере, запрет холодной экструзии, запрет джога без home, подтверждение выше 250 °C, лимит частоты, лимит `M500`, токен-авторизация, аудит команд по устройствам |
| **Диагностика прошивки** | по `M115 Cap:` и `M503` приложение само предупреждает: `EMERGENCY_PARSER` выключен, EEPROM недоступен, стол в bang-bang, зонда нет в прошивке |

## Структура

```
src/
  protocol/     чексуммы, парсер ответов Marlin, транспортный автомат (Link)
  transport/    serial (SerialPort) и mock (эмулятор), перечисление портов
  sim/          эмулятор Marlin — разработка и тесты без принтера
  printer/      модель состояния, разбор M503, слой безопасности и лимиты

web/            интерфейс: HTML + ES-модули, без бандлера и без CDN
test/           38 тестов: протокол, printer-слой, сервер
docs/           исследование, план, чек-лист разведки
reference/      конфиги стоковой и комьюнити-прошивок KP5L
```

## Короткая версия вердикта

Реализуемо, сложность средняя. Канал — `SERIAL_PORT 3` → CH340 → USB, 115200; тачскрин UART не
занимает, порт наш целиком.

**3DTune — это хост, а не прошивка.** Параметры (PID, шаги/мм, offset зонда, сетка, Z-offset)
настраиваются по USB и сохраняются в EEPROM. А *включение* самого 3D Touch, алгоритм левелинга и
лимиты температур — параметры времени компиляции.

Хорошая новость из исследования: стоковые архивы KP5L «autolevel» и «manual level» содержат
**побайтово одинаковый** `Robin_nano.bin` и различаются **одной строкой** в `robin_nano_cfg.txt`
(`cfg_leveling_mode 0` → `1`). Если Фаза 0 подтвердит поддержку зонда в стоке, включение 3D Touch —
правка текстового файла на SD-карте, а не пересборка.

Ещё: доступ по локальной сети **не отменяет USB-кабель** — кабель держит одна машина (Windows-ПК,
мини-хост или мак с кабелем USB-C→USB-B), остальные подключаются браузером. Подробнее — PLAN §3.
