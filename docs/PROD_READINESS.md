# Критерии готовности 3DTune к личной эксплуатации

Текущая цель — не публичный продукт и не публикация в магазине, а **надёжный личный инструмент
владельца одного KP5L**: можно держать хост рядом с принтером и управлять с ПК или своего телефона
в локальной сети. Приложение командует нагревателем на 250 °C и шаговиками, поэтому требования
безопасности машины не ослабляются; упаковка, массовая поддержка и публичный onboarding пока не
являются блокерами.

Статусы: ✅ выполнено и проверено · ⚠️ частично · ❌ не сделано · ❓ не проверено

---

## S. Безопасность машины (блокирующая категория)

Ни один программно проверяемый пункт здесь не может остаться ❌ перед личным использованием;
пункты про конкретное железо закрываются владельцем по ручному чек-листу.

| # | Критерий | Статус |
|---|---|---|
| S1 | Все команды нагрева и движения клампятся **на сервере**; браузерная валидация только UX | ✅ |
| S2 | Экструзия запрещена ниже `minExtrudeTemp` | ✅ |
| S3 | Движение по XYZ запрещено без выполненного home | ✅ |
| S4 | Цель выше `confirmAboveHotend` требует явного подтверждения | ✅ |
| S5 | E-Stop доставляет `M112` вне очереди и **сообщает об ошибке**, если связи нет | ✅ |
| S6 | Приложение предупреждает, когда `EMERGENCY_PARSER` выключен и STOP будет с задержкой | ✅ |
| S7 | Лимиты температур согласованы с прошивкой, а не только зашиты в хосте | ⚠️ переопределяются через конфиг, но сверка — ручной пункт Фазы 0 |
| S8 | **Таймаут «мёртвого человека»**: нагрев включён, клиентов нет N минут → остудить или громко предупредить | ✅ через **30 минут** (решение владельца, `deadmanMinutes` в конфиге): `M27`; idle → `M104 S0`/`M140 S0`, SD-печать/unknown → оставить, предупредить, проверить снова |
| S9 | Обрыв USB при включённом нагреве: понятное состояние в UI + инструкция «выключи питание» | ✅ критический баннер + инструкция + автореконнект |

## Зафиксированная политика для личного использования (S8, S10)

При уходе последнего web-клиента запускается тридцатиминутный таймер (значение по умолчанию — решение владельца; меняется полем `deadmanMinutes` в `~/.3dtune/config.json`, `0` полностью отключает). По его окончании, а также при
SIGINT/SIGTERM, хост запрашивает у Marlin состояние SD-печати командой `M27`:

- только однозначный `Not SD printing` разрешает отправить `M104 S0` и `M140 S0`;
- `SD printing byte ...`, неизвестный ответ, таймаут или потеря связи запрещают вмешательство;
- отказ от отключения не происходит молча: причина остаётся в журнале, выводится в консоль, а при
  отсутствии клиентов проверка повторяется каждые 10 минут;
- политика не требует постоянно включённого ПК: настройки и сетка по-прежнему живут в EEPROM,
  а автономная печать с SD не прерывается.

## Определение готовности

Личную сборку можно считать готовой к эксплуатации, когда:

1. **Вся категория S — ✅.** Без исключений и без ❓.
2. P, N, R — не осталось ❌; допустимые ⚠️ описаны с явной причиной.
3. U — ✅ кроме пунктов, требующих физического устройства, и те проверены вручную.
4. T1–T5, T8 — ✅.
5. Пройдена [Фаза 0](PHASE0_DISCOVERY.md) на реальном принтере, и результат не противоречит
   допущениям, зашитым в `limits.ts` и в разборе `M503`.
6. Есть регрессионный чек-лист для ручного прогона на железе.

## Что блокирует прямо сейчас

Программных ❌ больше нет; остаются проверки, требующие конкретного принтера или личного устройства:

- **Фаза 0 / живое железо** — реальные `M115`/`M503`, занятый serial, power cycle EEPROM и iOS
  Safari нельзя честно закрыть на эмуляторе.
- **R9, U4, T7** — нужны длительный soak и отдельный accessibility/flakiness прогон.
