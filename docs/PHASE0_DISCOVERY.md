# Фаза 0 — разведка на живом принтере (~20 минут, без кода)

**Зачем.** Всё исследование опирается на конфиги, скачанные из интернета. Твой принтер может
работать на другой прошивке. Если `M500` на нём не работает или `M503` ничего не отдаёт — план
меняется. Эти 20 минут решают, какой будет Фаза 1.

Ничего писать не надо: подключаешься любым готовым терминалом и вбиваешь команды.

## Инструмент

Любой из:
- **Pronterface** (Printrun) — есть сборки под Windows и macOS
- **PrusaSlicer / OrcaSlicer** → вкладка с консолью принтера
- голый терминал: `screen /dev/cu.usbserial-XXXX 115200` (macOS) — выход `Ctrl-A`, `K`

**macOS:** открывать **`/dev/cu.*`**, не `/dev/tty.*`. `tty.*` дёргает DTR при открытии и может
ресетить плату. Если устройства нет вовсе — нужен драйвер CH340:
[WCHSoftGroup/ch34xser_macos](https://github.com/WCHSoftGroup/ch34xser_macos).

**Windows:** драйвер CH340 от WCH, порт будет `COMx`.

Скорость: **115200**.

### 4a. Лимиты температур — приложение их не может узнать само

Marlin **не отдаёт** `HEATER_0_MAXTEMP` / `BED_MAXTEMP` ни в `M503`, ни в `M115`. 3DTune
использует зашитые рабочие потолки (сопло 265 °C, стол 110 °C) — намеренно **ниже** порогов
аварийного отключения из стокового `robin_nano_cfg.txt` (275 / 150).

- [ ] Значение `HEATER_0_MAXTEMP` в твоей прошивке: `______`
- [ ] Значение `BED_MAXTEMP`: `______`

Если твоя сборка ограничена жёстче (например сопло 250) — поправь в `~/.3dtune/config.json`:

```json
{ "limits": { "hotendMax": 240, "confirmAboveHotend": 230 } }
```

Иначе приложение позволит задать цель, которую прошивка не выполнит, и UI покажет
недостижимое значение.

### 6. Аварийная остановка — ОПЦИОНАЛЬНО, делать последним

> **Нужный ответ уже получен в шаге 1.** `Cap:EMERGENCY_PARSER` из `M115` отвечает на вопрос
> полностью. Живой тест `M112` — только подтверждение, он **не обязателен**.
>
> ⚠️ **`M112` останавливает плату и требует выключения-включения питания.** Это штатное поведение
> Marlin, не поломка. Делать: только когда ничего не печатается, сопло не выше **150 °C**,
> и это последний пункт разведки.

Если решил проверить — разогреть сопло до 150 °C, затем:
```
M112
```
- [ ] Остановка мгновенная (а не через пару секунд): `да / нет`
- [ ] Плата встала, нужен power cycle: `да / нет` (ожидаемо «да»)

> Если `Cap:EMERGENCY_PARSER` = 0 и/или реакция с задержкой — `EMERGENCY_PARSER`
> обязателен в профиле прошивки (см. RESEARCH.md §6). Это P0: приложение будет гонять
> сопло на 240 °C восемь циклов `M303`, кнопка STOP должна работать мгновенно.

## Ветвление плана по результатам

| Результат разведки | Что делаем в Фазе 1 |
|---|---|
| `M115` даёт `Cap:`, `M503` полный, `M500` переживает питание | **Ветка A.** Пишем приложение сразу на стоковой прошивке. Прошивку меняем позже, только ради `EMERGENCY_PARSER`/`ADVANCED_OK`/BILINEAR |
| `M503` работает, но `M500` не сохраняет | **Ветка B.** Сначала шьём комьюнити-Marlin 2.1.x (`spinixguy` ABL), потом приложение |
| `Cap:`-строк нет, `M503` урезан / отвечает мусором | **Ветка C.** Стоковая прошивка — закрытая MKS-сборка без нормального GCode-контракта. Прошивка комьюнити-Marlin — **обязательное первое действие**, приложение строим только на ней |
| Плата не Robin Nano (например KP Cheetah / Klipper) | **Стоп.** Пересматриваем: на Klipper-плате правильный путь — Moonraker API, а не serial-хост. Пересоставить план |

### Отдельно про 3D Touch — возможен дешёвый путь

Если п. 4 показал, что **зонд в стоковой прошивке поддержан** (`Cap:Z_PROBE` / `M851` отвечает /
`G29` проходит), то включение автолевелинга — это **правка одной строки в `robin_nano_cfg.txt`
на SD-карте**, без пересборки и без тулчейна:

```diff
- >cfg_leveling_mode 0
+ >cfg_leveling_mode 1
```

(проверено: «autolevel» и «manual level» стоковые архивы KP5L содержат **побайтово одинаковый**
`Robin_nano.bin` и различаются ровно этой строкой — см. RESEARCH.md §2).

Прошивка комьюнити-Marlin тогда нужна не для 3D Touch, а только ради `EMERGENCY_PARSER`,
`ADVANCED_OK` и `PIDTEMPBED` — и её можно отложить до Фазы 3.

Заполненный чек-лист коммитим в `reference/live/`.
